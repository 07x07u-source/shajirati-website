# تقرير تنفيذ موقع شجيرتي الرسمي

> ملاحظة: هذا تقرير تاريخي لمرحلة إنشاء الموقع. إعدادات النشر الحالية على Render وحالة `app-ads.txt` موثقة في `SHAJIRATI_RENDER_DEPLOYMENT_REPORT_AR.md` و`RENDER_DEPLOYMENT_GUIDE_AR.md`، وهما المرجع الأحدث عند التعارض.

تاريخ التقرير: 15 أكتوبر 2026
حالة المشروع: مكتمل محليًا وجاهز للمراجعة قبل النشر
حالة النشر: لم يُنشر، ولم يُربط بدومين، تنفيذًا لطلب المالك

## 1. النتيجة التنفيذية

تم إنشاء موقع رسمي عربي مستقل داخل مجلد `website` من دون تعديل تطبيق Flutter أو Supabase أو Edge Functions أو Pl@ntNet أو AdMob داخل التطبيق. الموقع ليس قالب Landing Page منفردًا؛ بل منصة ثابتة متعددة الصفحات تضم العرض التسويقي، مركز الدعم، الأسئلة الشائعة، التحميل، التحديثات، والسياسات القانونية.

التقنية المستخدمة:

- Next.js 16.4.1 مع App Router.
- React 19.1.1 وTypeScript.
- Tailwind CSS مع طبقة تصميم مخصصة في CSS.
- Static Export عبر `output: "export"`.
- مكوّن Client واحد فقط للقائمة المتجاوبة؛ بقية الصفحات Server Components ثابتة.
- خط IBM Plex Sans Arabic محلي لتقليل الاعتماد على خدمات خارجية.

## 3. مطابقة المحتوى مع التطبيق الفعلي

تمت قراءة كود التطبيق قبل صياغة السياسات. أبرز الحقائق التي انعكست في الموقع:

- لا توجد حسابات مستخدمين في النسخة الحالية.
- صورة التعرف تُرسل عبر Supabase Edge Function إلى Pl@ntNet؛ لذلك لا يدعي الموقع أنها لا تغادر الجهاز.
- دالة التعرف الحالية لا تكتب الصورة الخام في قاعدة بيانات أو Supabase Storage، لكن لا توجد وعود بشأن احتفاظ الخدمات الخارجية خارج ما يملكه مشغل شجيرتي.
- كاش التعرف المحلي يحتفظ بالنتيجة وبصمة SHA-256، بحد أقصى 20 نتيجة ولمدة 30 يومًا وفق الكود الحالي، لا ببايتات الصورة الخام.
- كاش بيانات العناية مدته 365 يومًا، وكاش الأسعار 90 يومًا، وبحد أقصى 40 عنصرًا وفق الكود الحالي.
- عناصر «مزرعتي» ونسخ صورها محفوظة محليًا في جهاز المستخدم.
- حذف العنصر من «مزرعتي» يزيل السجل، لكن ملف الصورة المنسوخ قد يبقى؛ لذلك تشرح صفحة حذف البيانات أن مسح بيانات التطبيق أو إلغاء تثبيته هو المسار الأشمل حاليًا.
- الإعلانات مرتبطة بـGoogle Mobile Ads مع UMP والتحقق من `canRequestAds()`، وتظهر في التفاصيل و«مزرعتي» فقط حسب التكامل الحالي، لا في الكاميرا أو المعالجة أو أول ظهور للنتيجة.
- الأسعار تقديرية لدول الخليج وليست عروض بيع أو أسعارًا ملزمة.

لا يدعي الموقع دقة تعرف 100% أو توافقًا قانونيًا كاملًا.

## 4. التصميم وتجربة الاستخدام

تم بناء نظام بصري بطابع Premium Nature Technology:

- اللون الأساسي `#234B35` والخلفية `#F7F0E5` مع تدرجات طبيعية هادئة.
- شريط تنقل زجاجي عائم مع Backdrop Blur وحد رفيع وظل خفيف.
- بطاقات كبيرة وحواف ناعمة وتباين واضح.
- عرض هاتف يستخدم لقطة الكاميرا الفعلية من التطبيق.
- صور فعلية لشاشات الكاميرا، النتيجة، التفاصيل، و«مزرعتي». شاشة التطبيق الرئيسية الحالية هي الكاميرا، لذلك لم تُخترع شاشة خامسة غير موجودة.
- قسم أمثلة نباتية يتضمن نخيل التمر، واشنطونيا، النخيل الملكي، فيكس بنجامينا، وأشجار الزينة الشائعة، مع الأسماء العلمية ونسب المصادر المتاحة.
- قائمة جوال قابلة للوصول، أزرار لمس كبيرة، Focus واضح، ورابط تخطّي للمحتوى.
- دعم تلقائي للوضع الداكن وتباين متكيف.

وفي تمريرة التحسين النهائية أضيفت تفاصيل تقلل الطابع القالبي وتوضح قيمة المنتج بسرعة أكبر:

- حقائق مختصرة داخل الواجهة الأولى عن الصور والدول والتخزين المحلي.
- قسم مستقل يشرح درجة الثقة والبدائل وطريقة تحسين النتيجة، مع لقطة نتيجة حقيقية من التطبيق.
- توزيع Bento أكثر وضوحًا لبطاقات المميزات، وتلميح بصري لاستكشاف شريط الأنواع.
- لمعان حواف أدق للزجاج، مؤشر تقدم تمرير رفيع، ومسافات رأسية أكثر اتزانًا.
- أُعيد بناء الاتجاه البصري بوصفه «مرصدًا نباتيًا حيًا»: افتتاحية داكنة غامرة، شبكة رصد، مسار مسح ضوئي فوق صورة الشجرة، مدارات ضوئية، وهاتف فعلي يطفو داخل المشهد.
- حصلت الصفحات الداخلية على مشاهد افتتاحية موحدة وعميقة بدل ترويسة نصية مسطحة، مع الحفاظ على هوية شجيرتي العربية.

## 5. الحركة والأداء

- حركات ظهور مرتبطة بالتمرير باستخدام CSS فقط عند دعم المتصفح.
- Hover وPress feedback خفيفان من دون مكتبة Animation.
- حركة طفو بطيئة للعرض الرئيسي، مع تأثيرات نابضية خفيفة للبطاقات ولمعة تمر فوق الأزرار.
- انتقال دخول ضبابي بين المسارات عبر `app/template.tsx`، وظهور متتابع للعناصر باستخدام `IntersectionObserver` صغير بدل مكتبة حركة كبيرة.
- شريط معلومات متحرك، مسح بصري للشجرة، مدارات بطيئة، Parallax خفيف مع المؤشر، وحركات Hover متدرجة للبطاقات والشاشات.
- جميع الحركات تتوقف تلقائيًا عند تفعيل `prefers-reduced-motion`.
- `prefers-reduced-motion` يعطل الحركات والتمرير السلس للمستخدم الذي يطلب تقليل الحركة.
- لا توجد مكتبات JavaScript خارج إطار Next/React.
- الصور لها أبعاد معروفة لمنع CLS، وتُحمّل الصور أسفل الصفحة كسولة افتراضيًا.
- صور Hero المحتملة كعنصر LCP تستخدم `loading="eager"` وفق دليل Next.js 16.
- الخطوط مستضافة محليًا.
- التصدير ثابت بالكامل إلى `out/`، ما يسمح بتقديمه من CDN.

لم يتم تشغيل Lighthouse على Production لأنه لا يوجد رابط منشور. لذلك لا توجد مطالبة بدرجة 90 أو أكثر قبل القياس الفعلي بعد النشر.

## 6. SEO

تم تنفيذ:

- Title وDescription مستقلان لكل صفحة.
- Canonical URL لكل صفحة، بما فيها صفحة 404.
- Open Graph وTwitter Cards.
- `robots.txt` و`sitemap.xml` مولدان أثناء البناء.
- Web Manifest وأيقونة التطبيق.
- Structured Data من نوعي `WebSite` و`SoftwareApplication`.
- كلمات عربية مستهدفة من دون وعود مضللة.
- روابط داخلية كاملة مع `trailingSlash` متناسق.

يُشتق الدومين من `NEXT_PUBLIC_SITE_URL`. عند البناء المحلي يستخدم `http://localhost:3000`، ويجب ضبط الدومين الرسمي قبل إنتاج نسخة النشر.

## 7. الصفحات القانونية والخصوصية

تغطي المسودات:

- صور التعرف ومسار المعالجة عبر Supabase وPl@ntNet.
- التخزين المحلي والكاش وبصمات الصور.
- Google Mobile Ads وUMP وخيارات إدارة الخصوصية.
- حقوق المستخدم، الأمان، الحذف، والتواصل.
- حقوق الصور والملكية الفكرية.
- الاستخدام المقبول والخدمات الخارجية.
- حدود الاعتماد على التعرف والعناية والأسعار.
- ملفات ارتباط الموقع الحالي، مع التنبيه إلى تغير السياسة إذا أضيفت أدوات قياس مستقبلًا.

جميع النصوص موسومة بوضوح كمسودات تحتاج مراجعة قانونية قبل النشر. لم يُخترع اسم جهة مالكة أو قانون واجب التطبيق.

## 8. Google Play وAdMob

- صفحة خصوصية عامة جاهزة لتزويد Google Play برابطها بعد النشر.
- صفحة حذف بيانات مستقلة لا تدعي وجود «حذف حساب» لأن التطبيق لا يستخدم حسابًا.
- `public/app-ads.txt` جاهز تقنيًا ويُنسخ إلى `out/app-ads.txt`.
- المسار المحلي أعاد `200` و`Content-Type: text/plain; charset=UTF-8`.
- الملف لا يحتوي App ID أو Ad Unit ID أو سجل ناشر مختلق.
- تعليمات الإعداد موجودة في `APP_ADS_SETUP_AR.md`.
- يجب نسخ سجل الناشر الرسمي من حساب AdMob قبل النشر.

## 9. إعداد البريد والدومين والمتجر

تُضبط البيانات من متغيرات البيئة:

```text
NEXT_PUBLIC_SITE_URL=
NEXT_PUBLIC_SUPPORT_EMAIL=
NEXT_PUBLIC_LEGAL_OWNER=
NEXT_PUBLIC_GOOGLE_PLAY_URL=
NEXT_PUBLIC_APP_STATUS=coming-soon
```

يبقى زر التحميل في حالة «قريبًا» ما دام الرابط غير معتمد. لا يعرض الموقع بريدًا أو رقم هاتف أو عنوانًا وهميًا، ولا يوجد نموذج يزعم نجاح الإرسال.

## 10. خطوات Vercel وDNS بعد الموافقة

لم تُنفذ الخطوات التالية؛ هي دليل تسليم فقط:

1. إنشاء مشروع Vercel من مجلد `website`.
2. إضافة متغيرات Production المعتمدة.
3. بناء Preview ومراجعة السياسات والهوية.
4. إضافة الدومين من لوحة Vercel.
5. نسخ سجلات DNS التي تعرضها Vercel إلى مزود الدومين حرفيًا.
6. انتظار انتشار DNS وشهادة TLS.
7. التحقق من الدومين الأساسي ونسخة `www` وإعداد التحويل المفضل.
8. فحص `/app-ads.txt` و`/robots.txt` و`/sitemap.xml` على الدومين النهائي.
9. إدخال رابط الخصوصية وحذف البيانات والدومين في Google Play Console حيث يلزم.
10. ربط الدومين المعتمد في AdMob وطلب إعادة فحص `app-ads.txt`.

## 11. نتائج الاختبارات

| الفحص | النتيجة |
|---|---|
| `npm run lint` | ناجح، صفر أخطاء وتحذيرات |
| `npm run typecheck` | ناجح |
| `npm run build` | ناجح على Next.js 16.4.1 |
| التصدير الثابت | 22 مسارًا مولدًا، منها 17 صفحة عامة مطلوبة |
| `npm run validate` | نجح: 17 مسارًا و19 ملف HTML والروابط وجذور SEO و`app-ads.txt` |
| `npm audit --omit=dev` | صفر ثغرات معروفة وقت الاختبار |
| HTTP محلي للرئيسية | `200` و`text/html` |
| HTTP محلي لصفحة مجهولة | `404` حقيقي |
| HTTP محلي لـ`app-ads.txt` | `200` و`text/plain` |
| فحص RTL | `lang="ar"` و`dir="rtl"` في جميع ملفات HTML |
| عرض جوال 390×844 | ناجح، لا تمرير أفقي، وقائمة الجوال تعمل |
| عرض سطح مكتب 1280×720 و1440×1000 | ناجح، لا تجاوز أفقي، وتخطيط ثنائي الأعمدة يعمل |
| صفحة الخصوصية على الجوال | ناجحة، 11 قسمًا، بلا تجاوز أفقي |
| Console في تبويب تحقق جديد | صفر أخطاء وصفر تحذيرات |

تم كذلك استبدال خادم المعاينة المحلي الثقيل بخادم ثابت خفيف بعد أن تسبب نقص مساحة القرص في انهيار عملية PostCSS داخل وضع تطوير Next.js. النسخة المبنية نفسها سليمة، والمعاينة الحالية تعيد `200` ولا تستخدم HMR.

تم تحديث Next.js من نسخة قديمة متأثرة بتحذير أمني إلى 16.4.1، ثم أُعيد التدقيق حتى أصبح `npm audit` نظيفًا. المرجع الرسمي: `https://nextjs.org/blog/CVE-2025-66478`.

## 12. ما يحتاج مراجعة المالك قبل النشر

- الدومين الرسمي.
- بريد الدعم والخصوصية.
- الاسم القانوني للمالك أو الجهة.
- رابط Google Play النهائي وحالة النشر.
- سجل الناشر الرسمي في `app-ads.txt`.
- مراجعة قانونية سعودية/دولية للنصوص، بما يشمل PDPL ونطاق الدول المستهدفة.
- التحقق من مدد وسياسات الاحتفاظ لدى Pl@ntNet وGoogle وفق الحسابات والعقود الفعلية.
- قياس Lighthouse على رابط Production ومعالجة أي فروق ناتجة عن CDN أو الدومين.
- مراجعة نهائية للصور والتراخيص ونصوص التسويق.

## 13. الخلاصة

الموقع مكتمل محليًا، متعدد الصفحات، ثابت، سريع البنية، متجاوب، عربي RTL، ويعكس حقائق التطبيق الحالية بوضوح. لا توجد عملية نشر أو ربط دومين أو سياسة رسمية منشورة ضمن هذا التسليم، وتبقى البنود المذكورة أعلاه مطلوبة قبل الإطلاق العام.
